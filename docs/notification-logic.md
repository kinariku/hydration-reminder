### 通知ロジック仕様（現行実装）

このドキュメントは、現在の通知スケジューリングと文面仕様を実装準拠でまとめたものです。対象モジュールは次の通りです。

- 初期スケジュール/朝通知起点: `lib/notifications/button.ts`
- スヌーズ通知: `lib/notifications/snooze.ts`
- 動的プラン（現在は未使用候補）: `lib/notifications/planning.ts`
- レガシー一括スケジュール（未使用）: `lib/notifications/legacy.ts`
- テスト通知: `lib/notifications/background.ts`

---

### 1) 初回通知の基準（頻度に連動）

- 画面設定の通知頻度に応じて、次の1発目を現在時刻からオフセットして登録します。
  - high: 30分後
  - medium: 60分後
  - low: 90分後
- 実装: `scheduleButtonTriggeredReminders` 内で `baseIntervalMin` を頻度別に設定。

---

### 2) 提案量 suggestMl（頻度連動 + 残量上限）

- 目標量 `targetMl` に対する割合を頻度別に適用し、最小/最大の範囲でクランプ。さらに残量 `remainMl` を超えないよう上限。
  - high: 7%（150–300ml）
  - medium: 10%（200–400ml）
  - low: 13%（250–500ml）
- 実装: `scheduleButtonTriggeredReminders` 内で算出し、スヌーズ登録時に `suggestMl` として渡す。

---

### 3) スヌーズ（ユーザー入力優先 + 漸増間隔）

- ベース間隔はユーザー設定 `settings.snoozeMinutes` を最優先。未設定時は頻度の既定を採用。
  - 既定値: high=8分, medium=10分, low=15分
- 上限/下限: 5分以上、かつ最大30分。
- 登録方式:
  - 初回スヌーズは `baseTime`（= 初回通知時刻）で登録。
  - 2回目以降は「漸増」方式で、都度の実間隔を広げていく。
    - 増加幅はベース間隔に対する比率で頻度別に設定（最小幅あり）。
      - high: ベース×25%（最小+1分）
      - medium: ベース×30%（最小+2分）
      - low: ベース×33%（最小+3分）
    - 各スヌーズの実間隔 = min(30分, ベース + i×増加幅)。累積して次時刻を計算。
- 回数:
  - 頻度既定: high=7回, medium=5回, low=3回
  - ただし実装全体の上限として「初回 + 5件」まで（最大6件）に制限されています。
    - 実装: `SNOOZE_CONFIG.maxSnoozes=5` により、総登録は `min(頻度回数+1, 6)` 件。

---

### 4) 通知メッセージ（絵文字なし、進捗入り）

- スヌーズ初回/継続の本文には、提案量と現在/目標を表示します。
  - タイトル: 「水分補給リマインダー」
  - 本文（初回例）: 「水分補給の時間です！{suggestMl}ml どうですか？ 現在: {consumedMl}ml / 目標: {targetMl}ml」
  - 本文（継続例）: 「{メッセージ} 現在: {consumedMl}ml / 目標: {targetMl}ml」
- 朝通知の本文は「今日も水分補給を始めましょう。目標は {targetMl}ml です。」
- 動的プラン通知（未使用時でも整合）: 
  - タイトル: 「水分補給リマインダー」
  - 本文: 「いま {suggestMl}ml いきますか？ 現在/目標 + 次回予定（xx分後、hh:mm頃）」

---

### 5) 実装の責務分担

- `scheduleButtonTriggeredReminders`
  - 初回時刻（頻度）・提案量（割合/クランプ）・スヌーズ基準（ユーザー入力優先）を決定
  - スヌーズ連鎖を `scheduleSnoozeReminders` に依頼
  - 7日分の「朝通知」を未重複で追加

- `scheduleSnoozeReminders`
  - 初回と「漸増」間隔のスヌーズを連続登録（最大で初回+5件）
  - 文面に「現在/目標」を付与

- `planning.ts`（任意採用可）
  - ペースに応じて「次回までの分数」と「提案量」を動的算出
  - 文面に「現在/目標」を付与する対応済み

---

### 6) 想定サンプル（具体的な時刻と量）

前提: 今日 10:00 時点 / 目標 2000ml / 現在 600ml / ユーザーのスヌーズ入力 12分

- 高頻度（high）
  - 初回通知: 10:30（現在+30分）
  - 提案量: 目標の7% = 140ml → クランプ150〜300 → 150ml（残量1400ml以内）
  - スヌーズ（ベース=12分, 増加幅=+3分ずつ, 最大30分, 総登録は初回+最大5件）
    - 1本目: 10:30（初回）本文 例:「水分補給の時間です！150ml どうですか？ 現在: 600ml / 目標: 2000ml」
    - 2本目: 10:42（+12）本文 例:「喉が乾いていませんか？… 現在: 600ml / 目標: 2000ml」
    - 3本目: 10:57（+12+15）
    - 4本目: 11:15（+12+15+18）
    - 5本目: 11:36（+12+15+18+21）
    - 6本目: 12:00（+12+15+18+21+24）

- 中頻度（medium）※ユーザーのスヌーズ未設定の場合（既定10分, 増加幅+3分）
  - 初回通知: 11:00（現在+60分）
  - 提案量: 目標の10% = 200ml → クランプ200〜400 → 200ml
  - スヌーズ: 11:00 初回 → 11:10 → 11:23 → 11:39 → 11:58 → 12:20 …（上限・枠内）

- 低頻度（low）※ユーザーのスヌーズ未設定（既定15分, 増加幅+5分）
  - 初回通知: 11:30（現在+90分）
  - 提案量: 目標の13% = 260ml → クランプ250〜500 → 260ml
  - スヌーズ: 11:30 初回 → 11:45 → 12:05 → 12:30 → 13:00 → 13:35 …（上限・枠内）

注記:
- スヌーズは最大で「初回 + 5件」の登録枠があり、それ以上は打ち切られます（総6件）。
- 提案量は「残量」が少ない場合、残量が優先されます（例: 残り120mlなら提案量=120ml）。
- 朝通知は翌日以降7日分を重複チェックして追加します（タイトル「おはようございます」）。
